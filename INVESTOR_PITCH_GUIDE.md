## DATA FLOW: INVOICE UPLOAD → RECOMMENDATION

```
1. USER UPLOADS INVOICE (PDF)
   │
   ├─> Frontend: Validate file (size, type)
   ├─> Upload to S3 (encrypted)
   └─> Trigger parsing job
   
2. PDF EXTRACTION
   │
   ├─> pdf-parse library extracts text
   ├─> OCR fallback if text extraction fails
   └─> Send text to AI service
   
3. AI PARSING (Claude 3.5)
   │
   ├─> Check Redis cache (hash of text)
   │   └─> 95% cache hit → Return cached result
   │
   ├─> If cache miss:
   │   ├─> Call Claude API with optimized prompt
   │   ├─> Parse response (vendor, amount, date, etc.)
   │   ├─> Validate extracted data
   │   └─> Cache result in Redis (24h TTL)
   │
   └─> Return parsed invoice object
   
4. CATEGORY INTELLIGENCE
   │
   ├─> Lookup vendor in database (95% hit rate)
   │   └─> If found → Use database category
   │
   ├─> If not found:
   │   ├─> Call Claude API for categorization
   │   ├─> Cache result in database
   │   └─> Return category
   │
   └─> Save invoice to PostgreSQL
   
5. AI ANALYSIS (14 modules run in parallel)
   │
   ├─> Price Increase Detection
   │   ├─> Query historical invoices for same vendor
   │   ├─> Calculate average (last 3 months)
   │   ├─> Compare: if (new > avg * 1.02) → Alert
   │   └─> Calculate annual impact
   │
   ├─> Duplicate Detection
   │   ├─> Hash invoice (vendor + amount + date)
   │   ├─> Check for duplicates in last 30 days
   │   └─> Flag if found
   │
   ├─> Payment Timing Optimization
   │   ├─> Analyze user's cash flow
   │   ├─> Calculate optimal payment date
   │   └─> Suggest delay if safe
   │
   ├─> Predictive Warnings
   │   ├─> Project balance 30 days forward
   │   ├─> Flag potential negative balance
   │   └─> Suggest actions
   │
   ├─> Fraud Detection (ML)
   │   ├─> Extract features (amount, time, vendor, etc.)
   │   ├─> Run through Isolation Forest model
   │   ├─> If anomaly score < threshold → Flag
   │   └─> Generate explanation
   │
   └─> [9 other modules...]
   
6. GENERATE RECOMMENDATIONS
   │
   ├─> Aggregate insights from all modules
   ├─> Prioritize by severity and impact
   ├─> Generate actionable recommendations
   └─> Save to database
   
7. NOTIFY USER
   │
   ├─> Push notification (if enabled)
   ├─> In-app alert
   └─> Email summary (daily digest)
   
8. USER TAKES ACTION
   │
   ├─> Approve price increase
   ├─> Find alternative (trigger search)
   ├─> Cancel subscription
   └─> Schedule payment
```
